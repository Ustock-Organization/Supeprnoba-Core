# Supernoba Lambda 도메인 재구조화 테스트 계획

## 프로젝트 개요
Supernoba 플랫폼의 Lambda 함수들이 도메인 기반으로 재구조화되었습니다.
- Supernoba-symbol-admin: Symbol 관리 전용
- Supernoba-admin-core: 사용자 관리 + 시스템 설정
- Supernoba-auth: X OAuth + User Init 통합

이 테스트 계획은 모든 신규/수정된 Lambda 함수의 기능을 검증합니다.

## 테스트 대상 Lambda

### 1. Supernoba-symbol-admin
- GET /symbols - 전체 종목 목록
- GET /symbols/{symbol} - 개별 종목 상세
- POST /symbols (action=listing) - 신규 종목 등록
- POST /symbols (action=activate) - 종목 활성화
- POST /symbols (action=approve) - 크리에이터 승인
- POST /symbols (action=reject) - 크리에이터 거절
- POST /symbols (action=restore) - 삭제된 종목 복원
- PUT /symbols/{symbol} - 종목 수정
- DELETE /symbols/{symbol} - 종목 삭제
- POST /sync - Redis 동기화
- POST /cleanChart - 차트 데이터 정리

### 2. Supernoba-admin-core
- GET /auth - 관리자 권한 확인
- GET /alerts - 관리자 알림 조회
- GET /users - 사용자 목록
- GET /users/{userId} - 사용자 상세
- POST /users (action=suspend) - 사용자 정지
- POST /users (action=unsuspend) - 사용자 정지 해제
- POST /users (action=setBalance) - 잔액 설정
- POST /users (action=setHolding) - 보유자산 설정
- POST /users (action=getAllHoldings) - 전체 보유자산 조회
- GET /settings/site - 사이트 설정 조회
- PUT /settings/site - 사이트 설정 변경
- GET /settings/tickerTape - 티커테이프 설정 조회
- PUT /settings/tickerTape - 티커테이프 설정 변경
- GET /settings - 전체 시스템 설정
- PUT /settings - 전체 시스템 설정 변경

### 3. Supernoba-auth
- GET /auth/x/init - X OAuth 시작
- GET /auth/x/callback - X OAuth 콜백
- POST /auth/x/refresh - 토큰 갱신
- GET /auth/init - 사용자 초기화 상태 확인
- POST /auth/init - 신규 사용자 초기화

## 테스트 항목

### Task 1: Symbol-Admin 공개 API 테스트
종목 목록 및 상세 조회 기능 테스트 (인증 불필요)
- GET /symbols 200 응답 확인
- GET /symbols/{symbol} 존재하는 종목 조회
- GET /symbols/{symbol} 존재하지 않는 종목 404 확인
- 검색 파라미터 (q=) 동작 확인

### Task 2: Symbol-Admin 관리자 API 테스트 - 종목 등록
신규 종목 등록 및 활성화 테스트 (관리자 인증 필요)
- POST listing 정상 등록 확인
- symbol 유효성 검증 (2-20자, 영숫자만) 테스트
- 중복 symbol 등록 시 409 에러 확인
- 필수 필드 누락 시 400 에러 확인
- POST activate 상태 변경 확인
- Redis active:symbols 동기화 확인

### Task 3: Symbol-Admin 관리자 API 테스트 - 종목 수정/삭제
종목 수정 및 삭제 기능 테스트

- status 변경 시 Redis 동기화 확인

- SQS 비동기 정리 메시지 전송 확인

### Task 4: Symbol-Admin 유틸리티 API 테스트

### Task 5: Admin-Core 인증 API 테스트

### Task 12: Auth 토큰 갱신 테스트

### Task 13: 보안 및 권한 테스트
인증/권한 관련 보안 테스트

- symbol 형식 검증 (injection 방지)
- CORS 헤더 확인

### Task 14: 에러 핸들링 테스트
에러 상황 처리 테스트

- 유효하지 않은 action 400
- 서버 에러 500 응답 형식 확인

### Task 15: 프론트엔드 통합 테스트
프론트엔드와 통합 테스트
- SystemSettingsService.js initializeUser 호출
- 새 엔드포인트 (/auth/init) 연결 확인
- 응답 형식 호환성 확인
- 에러 처리 확인

### Task 16: 성능 및 안정성 테스트
부하 및 연결 관리 테스트
- PostgreSQL 연결 풀 관리 확인
- 30초 idle timeout 후 연결 해제 확인
- Redis 연결 안정성 확인
- 동시 요청 처리 확인

## 성공 기준
- 모든 API 엔드포인트가 예상된 응답 반환
- 인증이 필요한 API가 적절히 보호됨
- 데이터 무결성 유지 (DynamoDB, Redis, PostgreSQL)
- 기존 프론트엔드와 하위 호환성 유지
- 에러 발생 시 적절한 에러 메시지 반환
